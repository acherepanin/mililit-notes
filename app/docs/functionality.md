# Функционал Приложения

## Авторизация

Приложение всегда открывается с формы входа. Без Bearer-токена пользователь не может открыть заметки, админку, статистику или историю.

Как работает вход:

- frontend отправляет `POST /api/auth/login`;
- backend ищет пользователя по `lower(username)`;
- пароль проверяется по сохраненному hash;
- при успешном входе обновляется `users.last_login_at`;
- событие входа пишется в `activity_logs`;
- frontend сохраняет токен в `localStorage` под ключом `notes.auth.token`;
- при следующем открытии frontend вызывает `GET /api/me` и восстанавливает пользователя.

Пользователь по умолчанию создается только при пустой таблице `users`. Он получает роль `admin`.

## Роли

Поддерживаются две роли:

- `user` - обычный пользователь, работает только со своими заметками.
- `admin` - пользователь с доступом к админ-панели, управлению пользователями, статистике и истории.

Новые пользователи по умолчанию получают роль `user`. Роль можно изменить только через админку или админский API. Backend не дает оставить систему без единого администратора.

## Изоляция Заметок

Каждая заметка имеет `user_id`. Все методы заметок используют `request.user.id` из токена:

- `GET /api/notes/tree` возвращает дерево только текущего пользователя;
- `GET /api/notes/:id` ищет заметку по `id` и `user_id`;
- создание дочерней заметки проверяет, что родитель принадлежит этому же пользователю;
- перенос заметки проверяет нового родителя и цепочку потомков внутри заметок текущего пользователя;
- удаление заметки не может удалить заметку другого пользователя.

Даже администратор в обычном разделе заметок видит только свои заметки. Управление пользователями и общая статистика вынесены отдельно в админку.

## Работа С Деревом Заметок

- одна кнопка создания в боковом меню сразу создает заметку с дефолтным названием `Новая заметка`;
- если выделена заметка, новая заметка создается дочерней; если выбран корень, новая заметка создается в корне;
- корень логически выбирается кликом по свободной области дерева заметок, но сама область при этом не подсвечивается;
- всплывающее окно создания заметки не используется;
- новую заметку можно сразу переименовать в дереве через иконку карандаша;
- при редактировании строки карандаш заменяется иконкой сохранения, `Enter` сохраняет название, `Escape` отменяет редактирование;
- в строке дерева есть отдельная иконка удаления, прижатая к правому краю вместе с редактированием;
- перенос заметки в корень выполняется drag-and-drop в свободную область дерева, отдельная панель `В корень` больше не отображается;
- если пользователь находится в панели администратора и кликает заметку в дереве сайдбара, рабочая область автоматически переключается на раздел заметок и открывает выбранную заметку;
- пункт `Заметки` в меню сайдбара из панели администратора открывает текущую выбранную заметку, а если ее нет - первую заметку из дерева;
- все ошибки создания, переименования и удаления выводятся через toast-alerting.

## Панель администратора

Панель администратора доступна только пользователям с ролью `admin`. На frontend она открывается отдельным режимом в рабочей области через группу разделов в меню сайдбара, а на мобильной версии из шапки панели доступна кнопка открытия бокового меню.

Вкладка пользователей:

- список всех пользователей в виде компактных строк управления, а не растянутой таблицы;
- создание нового пользователя через отдельное кастомное модальное окно;
- поиск пользователей по логину и кнопка добавления находятся в одной горизонтальной строке шапки списка пользователей;
- строка поиска занимает всю доступную ширину, кнопка добавления прижата справа и не переносится на новую строку на мобильной версии;
- содержимое вкладки пользователей выровнено с шапкой без дополнительных боковых отступов;
- логин существующего пользователя только отображается и не редактируется из интерфейса;
- смена пароля;
- смена роли `user`/`admin`;
- удаление пользователя со всеми его заметками.
- логин в строке пользователя выделяется отдельным фоном, текущая роль под логином не дублируется;
- каждая строка содержит только профиль, управление ролью, поле нового пароля и действия;
- поле роли в строке пользователя имеет отдельную иконку слева, как поле нового пароля;
- управление ролью и новым паролем визуально сгруппировано, кнопки сохранения и удаления прижаты к правому краю строки;
- строки используют ellipsis и подсказки для длинных логинов;
- на мобильных экранах карточка сохраняет компактную структуру: профиль остается слева, действия справа сверху, роль и пароль идут второй строкой;
- только на совсем узких экранах поля роли и пароля переходят в одну колонку, действия не уезжают в нижнюю отдельную зону.

Ограничения:

- администратор не может удалить собственный аккаунт;
- backend запрещает понизить последнего администратора до роли `user`;
- удаление пользователя каскадно удаляет его заметки через SQLite `ON DELETE CASCADE`.

Вкладка истории:

- показывает журнал важных действий в виде таблицы;
- вкладка истории использует смысловую иконку истории, а кнопки вкладок имеют единые hover/active-состояния без изменения размера;
- поддерживает поиск по действию, участникам и цели;
- сортировка даты вынесена в заголовок колонки;
- колонки пользователя, действия, инициатора и цели имеют компактные кастомные dropdown-фильтры с мультивыбором, счетчиком выбранных значений, текстовой очисткой и подсказками для реально обрезанных значений;
- события локализуются на текущий язык интерфейса;
- отображаются пользователь, дата, действие, инициатор и цель.

Вкладка статистики:

- всего пользователей;
- всего администраторов;
- всего заметок;
- всего событий истории;
- активные пользователи за текущий день;
- показатели оформлены отдельными цветными плитками, где описание находится в верхней строке справа от иконки;
- плитки раскладываются так, чтобы занимать всю доступную ширину родителя;
- если плитка остается без соседа в адаптивной сетке, она растягивается на всю ширину строки;
- содержимое статистики выровнено с шапкой без дополнительных боковых отступов;
- аналитические блоки показывают долю администраторов, активность за день, объем заметок/событий и средние значения на пользователя.

## История Действий

В `activity_logs` пишутся только значимые события:

- `auth.login` - вход пользователя;
- `notes.create` - создание заметки;
- `notes.update` - обновление заметки;
- `notes.move` - перенос заметки;
- `notes.delete` - удаление заметки;
- `admin.user.create` - создание пользователя администратором;
- `admin.user.update` - изменение пользователя администратором;
- `admin.user.delete` - удаление пользователя администратором.

История не пишет каждый ввод символа в редакторе. Обновление заметки фиксируется при сохранении.

## Язык и Тема

Поддерживаются языки:

- `ru` - русский, используется по умолчанию;
- `en` - английский.

Поддерживаются темы:

- `dark`;
- `light`.

Для авторизованного пользователя язык и тема сохраняются в БД через `PATCH /api/me/preferences`. Для гостевого экрана до входа значения временно хранятся в `localStorage`.

Все tooltips, toast-уведомления, модальные окна, кнопки, панель редактора, админка и история берут текст из текущего словаря.

## Редактор Заметок

Редактор построен на Tiptap.

Режимы:

- по умолчанию заметка открывается в режиме `Просмотр`: контент и название не редактируются, применяются форматирование и подсветка;
- режим `Редактирование` включается отдельной иконкой в панели редактора;
- в режиме просмотра ссылки кликабельны и открываются в новой вкладке;
- в режиме редактирования ссылки не открываются по клику, а при наведении показывают `href` в единой кастомной подсказке;
- элементы панели редактора сгруппированы по смыслу: режим, формат текста, блоки, вставки, история.

Поддерживается:

- жирный текст;
- курсив;
- подчеркивание;
- H1/H2/H3;
- маркированные и нумерованные списки;
- цитаты;
- inline code;
- code block;
- ссылки;
- undo/redo;
- кастомные copy fields;
- секретные copy fields для логинов, паролей, токенов и кредов;
- placeholder на текущем языке;
- сохранение `contentHtml` и `contentText`.

Ссылки:

- `Ctrl+K` или иконка ссылки открывает кастомную модалку;
- если текст выделен, ссылка применяется к выделению;
- если выделения нет, можно указать текст ссылки;
- ссылка сохраняется как `href`;
- внешняя ссылка сохраняется с `target="_blank"` и `rel="noopener noreferrer"`;
- визуально ссылка отображается отдельным inline-элементом с фоном и акцентной линией.

Copy field:

- вставляется отдельным Tiptap node `copyField`;
- хранит `data-label`, `data-value`, `data-kind` и `data-secret`;
- поддерживает типы `Текст`, `Логин`, `Пароль`, `Секрет`, `Токен`, `URL`;
- обычное copy field вставляется через иконку копи-поля или `Ctrl+Alt+C`;
- секретное copy field вставляется через иконку ключа или `Ctrl+Alt+P`;
- выбор типа вынесен в компактную иконку слева от поля, меню типов открывается поверх редактора через portal;
- показывает поле названия, поле значения и иконку копирования;
- для типа `Пароль` в режиме редактирования рядом со значением есть иконка автогенерации пароля;
- для типов `Пароль`, `Секрет` и `Токен` в режиме просмотра значение скрывается символами `*`;
- в режиме редактирования секретное значение вводится в password-поле;
- значение копируется через `navigator.clipboard.writeText`;
- после копирования кнопка временно меняет состояние.
- Маскирование работает только на уровне интерфейса: значение остается частью HTML заметки и не является шифрованием данных в SQLite.

## Работа с Кодом

Code block использует `@tiptap/extension-code-block-lowlight`, `lowlight` и кастомный React node view.

Режимы языка:

- `Авто` - язык не фиксируется, lowlight определяет его автоматически;
- выбор языка перенесен из общей панели в сам code block: dropdown находится в правом верхнем углу блока;
- в режиме просмотра dropdown виден, но недоступен для изменения;
- явные языки в dropdown: `Plain text`, `JSON`, `JavaScript`, `TypeScript`, `HTML/XML`, `CSS`, `SCSS`, `Bash`, `Shell`, `Markdown`, `YAML`, `SQL`, `Python`, `Java`, `C#`, `C++`, `Go`, `Rust`, `PHP`, `Ruby`, `Kotlin`, `Swift`, `Dart`, `Dockerfile`, `Nginx`, `GraphQL`, `INI`, `TOML`, `Diff`;
- если выбранного языка нет в lowlight-грамматиках или язык не зафиксирован, подсветка продолжает работать через auto-detect.

Форматирование кода:

- кнопка `{}` находится в группе блоков toolbar;
- hotkey `Ctrl+Alt+F`;
- работает, когда курсор находится внутри code block;
- JSON форматируется через `JSON.parse` и `JSON.stringify(..., null, 2)`;
- HTML/XML получает базовое форматирование по тегам;
- JS/TS/CSS/SCSS форматируются базовой отступной раскладкой;
- SQL переносит основные ключевые слова на новые строки;
- в режиме `Авто` formatter пытается распознать JSON, markup или SQL;
- если формат не распознан, удаляются только лишние пробелы справа;
- ошибки форматирования выводятся через toast.

## Горячие Клавиши

В topbar есть иконка клавиатуры. При наведении или фокусе она показывает доступные сочетания. Окно сочетаний рендерится через portal поверх модальных окон, dropdown и scroll-контейнеров.

Шапки заметок и панели администратора используют единый формат: слева заголовок/контекст, справа иконки управления, включая кнопку открытия/закрытия меню на мобильной версии.

| Клавиши          | Действие                                                 |
| ---------------- | -------------------------------------------------------- |
| `Ctrl+S`         | Сохранить заметку в режиме редактирования                |
| `Ctrl+Alt+N`     | Создать заметку в текущем фокусе дерева                  |
| `Ctrl+/`         | Фокус на поиск и открыть дерево                          |
| `Ctrl+K`         | Вставить или изменить ссылку в режиме редактирования     |
| `Ctrl+Alt+F`     | Форматировать текущий code block в режиме редактирования |
| `` Ctrl+Alt+` `` | Переключить code block в режиме редактирования           |
| `Ctrl+Alt+C`     | Вставить copy field в режиме редактирования              |
| `Ctrl+Alt+P`     | Вставить секретное copy field в режиме редактирования    |
| `Ctrl+Alt+T`     | Переключить тему                                         |
| `Ctrl+Alt+G`     | Переключить язык                                         |
| `Ctrl+\`         | Открыть дерево на мобильном экране                       |
| `Ctrl+B`         | Жирный                                                   |
| `Ctrl+I`         | Курсив                                                   |
| `Ctrl+U`         | Подчеркнуть                                              |
| `Ctrl+Z`         | Отменить                                                 |
| `Ctrl+Y`         | Повторить                                                |

На macOS вместо `Ctrl` работает `Cmd`, потому что обработчик проверяет `event.ctrlKey || event.metaKey`. Буквенные сочетания обрабатываются по физическим `KeyboardEvent.code`, поэтому работают на русской раскладке, а в подсказке отображаются английскими буквами.

## UI и Alerting

Нативные `alert`, `prompt`, `confirm` не используются.

Реализованы кастомные элементы:

- toast-alerts с временем жизни в правом верхнем углу, полупрозрачной поверхностью и blur-слоем;
- toast-alerts плавно появляются и исчезают, удаление из состояния происходит после exit-анимации;
- модальные окна имеют плавное появление и закрытие через кастомный слой, без native dialog;
- icon-only buttons из `lucide-react` с единым центрированием SVG внутри кнопки и четкой matte-оберткой без теней;
- обертки иконок используют тонкий нейтральный border, спокойную подложку и цвет состояния;
- внешний browser outline отключен глобально, чтобы элементы не получали системную рамку при фокусе или навигации клавиатурой;
- SVG внутри кнопок всегда наследуют цвет обертки, а primary/selected-состояния используют светлый контрастный цвет в темной теме;
- визуальная группировка иконок оставлена только у основных действий toolbar редактора заметок;
- остальные наборы иконок, включая дерево заметок и админку, отображаются без общей групповой рамки;
- кнопки `Сохранить`, `Удалить` и подсказка горячих клавиш в шапке заметки отображаются отдельными icon buttons без общей групповой подложки;
- кастомные dropdown-списки без native `select`;
- кастомные почти прозрачные тонкие scrollbars на всем сайте;
- кастомное дерево заметок с inline-переименованием, удалением из строки, выбором корня кликом по свободной области и переносом в корень через drop в свободную область дерева;
- компактный сайдбар работает в двух режимах: дерево заметок и полноценное меню;
- кнопка переключения режимов стоит на месте бывшего логотипа слева от заголовка, отображается только иконкой и использует общую tooltip-подсказку;
- в режиме меню скрываются поиск, кнопка создания и дерево заметок, а на их месте показываются сгруппированные разделы `Заметки`, `Панель администратора`, `Тема` и `Язык`;
- элементы меню используют компактные шрифты и иконки, но сохраняют увеличенные вертикальные отступы между пунктами;
- пункты разделов в меню не показывают правые текстовые статусы вроде `Выбрано` или `Сохранить`; у языка и темы справа остается только текущее значение;
- длинные названия пунктов и значения в меню сокращаются троеточием, а полный текст показывается через tooltip только при реальном обрезании;
- нижний отдельный индикатор статуса сохранения убран; состояние заметок подсвечивает иконку пункта `Заметки` и кнопку меню;
- единая кнопка создания заметки вынесена справа от поиска, все основные блоки выровнены по единому боковому отступу;
- мобильный сайдбар использует более прозрачную blur-поверхность и отдельную иконку сворачивания;
- панель администратора использует единый боковой inset для шапки вкладок, тулбаров, списков, таблиц и статистики;
- мобильная версия сохраняет внешний отступ и скругления основного рабочего блока как на desktop;
- единые hover/focus tooltips через portal поверх всех окон и scroll-контейнеров;
- интерактивные элементы на hover меняют цвет без scale/изменения размеров, на active используют мягкую прозрачность;
- светлая и темная темы используют общую систему токенов: несколько акцентных цветов и мягкие прозрачные поверхности без теней;
- sidebar на мобильной версии открывается и закрывается через более плавный transition;
- статичный фон без пассивных фоновых анимаций;
- во всей визуальной системе не используются CSS-градиенты: фон, панели, кнопки, графики, toast, dropdown и модальные окна строятся на однотонных цветах, прозрачности, border и shadow.

Dropdown-списки:

- используются в панели кода и админке;
- рендерятся поверх интерфейса через portal в `document.body`;
- при открытии считают свободное место сверху и снизу;
- раскрываются вниз или вверх в зависимости от доступного пространства;
- не обрезаются родительскими блоками со scroll/overflow;
- текст выбранного значения не наезжает на стрелку, потому что область текста и иконка разделены grid-разметкой;
- длинные значения сокращаются троеточием.
- таблица истории и остальные scroll-контейнеры используют тонкие почти прозрачные вертикальный и горизонтальный скроллы без `scrollbar-gutter`, поэтому контент не получает лишний отступ.

Длинный текст:

- значения в компактных элементах режутся через ellipsis;
- полный текст показывается в единой кастомной подсказке при наведении или фокусе, если значение реально обрезано троеточием;
- правило применяется к дереву заметок, строкам админки, истории действий и значениям dropdown.

Ошибки загрузки, сохранения, создания, удаления, переноса, авторизации, форматирования кода и админских операций выводятся через toast.
