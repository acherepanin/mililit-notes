# Функционал

## Авторизация

Приложение всегда требует вход.

По умолчанию при пустой БД создается admin:

- логин: `admin`
- пароль: `admin`
- роль: `admin`

Значения можно переопределить через `ADMIN_USERNAME` и `ADMIN_PASSWORD`.

## Роли

### `user`

- видит только свои заметки;
- создает, редактирует, перемещает и удаляет свои заметки;
- меняет язык и тему своего профиля.

### `admin`

Имеет все возможности `user`, а также доступ к панели администратора:

- управление пользователями;
- изменение роли и пароля;
- удаление пользователей вместе с их заметками;
- просмотр истории действий;
- просмотр статистики.

Backend не дает оставить систему без единого администратора.

## Заметки И Дерево

- Заметки хранятся иерархически через `parentId`.
- Каждый пользователь видит только свои заметки.
- Создание заметки выполняется одной кнопкой.
- Если выбрана заметка или папка, новая заметка создается дочерней.
- Если выбран корень, новая заметка создается в корне.
- Корень выбирается кликом по пустой области дерева, без визуальной подсветки корневого поля.
- Название заметки можно редактировать inline в дереве через иконку карандаша.
- При редактировании строки карандаш заменяется иконкой сохранения.
- `Enter` сохраняет название, `Escape` отменяет редактирование.
- Удаление доступно иконкой справа в строке дерева.
- Перемещение в корень выполняется drag-and-drop за пределы папки.
- Если пользователь находится в панели администратора и кликает заметку в сайдбаре, приложение переключается на заметки.
- Если заметка не выбрана, поля названия и даты в шапке редактора остаются пустыми.

## Sidebar

Сайдбар имеет два режима:

- дерево заметок;
- меню приложения.

В меню находятся:

- переход к заметкам;
- переход в панель администратора для admin;
- переключатель AI;
- настройки AI;
- переключение языка;
- переключение темы;
- выход.

В мобильной версии кнопка меню открывает и закрывает sidebar.

## AI-Ассистент

AI-функционал вынесен в отдельный модуль и по умолчанию выключен.

Доступно сейчас:

- переключатель AI в меню sidebar;
- настройки Notes AI открываются из кнопки настроек внутри самого AI-чата;
- плавающая иконка Notes AI в правом нижнем углу с увеличенным отступом от края, если Notes AI включен;
- компактный чат поверх интерфейса, который плавно раскрывается из AI-иконки;
- чат и настройки используют одно и то же всплывающее окно и переключаются внутри него, не создавая два конкурирующих popup;
- переключение между чатом и настройками не меняет размер родительского окна Notes AI;
- форма настроек Notes AI компактная: включение/выключение управляется только из sidebar, список провайдеров выбирается через кастомный выпадающий список, provider/base URL показываются только для варианта `Свой`, API key вынесен отдельной строкой, список моделей занимает все оставшееся пространство снизу и прокручивается внутри блока;
- у AI-иконки есть мягкая пассивная анимация, легкие частицы и почти незаметная тень;
- окно Notes AI использует более мягкий фон, спокойные border-цвета и легкую локальную тень, не меняя общие тени сайта;
- строка ввода в чате Notes AI оформлена как единый компактный composer: поле текста и кнопка отправки выровнены по высоте и визуально собраны в один блок;
- отдельная панель настроек provider: компактный список провайдеров OpenAI/OpenRouter/Groq/DeepSeek/Mistral/Qwen/Custom, `providerName`, `baseUrl`, `apiKey`, выбранная модель;
- API key, маска ключа, выбранная модель и состояние синхронизации сохраняются отдельно для каждой пары `providerName` + `baseUrl`; при переключении на ранее сохраненный провайдер эти данные подтягиваются из БД;
- сохранение API key только на backend в зашифрованном виде;
- отображение на frontend только маски `apiKeyHint`, без полного ключа;
- ручная синхронизация списка моделей через OpenAI-compatible `GET /models`;
- автоматическая синхронизация моделей после сохранения нового API key;
- фоновая синхронизация моделей раз в 24 часа для активных пользователей Notes AI с сохраненным ключом;
- локальный `ai_model_catalog` задает fallback-сигналы качества, сортировки и цены моделей; при наличии `AI_MODEL_CATALOG_URL` backend обновляет каталог из удаленного JSON-справочника при старте, раз в 24 часа и вручную из admin API;
- визуальное разделение моделей на бесплатные, платные, неизвестные и устаревшие;
- выбранная модель всегда отображается первой отдельной строкой в списке моделей и не дублируется ниже;
- модели сортируются внутри групп от более новых/приоритетных семейств к старым; если provider отдает `created`, это значение учитывается как дополнительный порядок внутри семейства;
- у каждой модели отображается цветовая полоска эффективности без числовой градации;
- в настройках моделей есть поиск по названию/id и фильтр `Все` / `Платные` / `Бесплатные`;
- у модели есть кастомная tooltip-подсказка с ценой за 1 миллион input/cached/output tokens; неизвестная цена отображается как `?`;
- выбор модели сохраняется сразу при клике, чтобы чат использовал актуальную модель без отдельного сохранения всей формы;
- проверка подключения;
- голосовой ввод в web-чате через браузерный Web Speech API: язык распознавания соответствует текущему языку UI, распознанный текст добавляется в composer, аудио не сохраняется и не отправляется на backend;
- Notes AI может возвращать карточки действий с подтверждением прямо в чате;
- в шапке мини-чата есть icon-кнопка очистки текущего диалога; пока Notes AI думает, кнопка отправки в composer заменяется на остановку активного запроса, а в ленте показывается компактная анимация троеточия без текста;
- успешные AI-действия отображаются в чате анимированной галочкой без текста, ошибки - анимированным крестиком и текстом ошибки; обычные ответы и уточняющие вопросы остаются текстовыми;
- визуальные статусы AI-действий не показывают текст успеха в интерфейсе, но их текстовый результат остается в истории диалога для модели, чтобы следующий запрос не воспринимался как продолжение уже выполненного действия;
- в настройках Notes AI есть переключатель `Подтверждать действия`: если он выключен, mutation-действия web-чата выполняются сразу без дополнительной кнопки подтверждения;
- через tool registry доступны поиск, чтение, создание, редактирование, удаление одной заметки, перенос всех активных заметок в корзину, восстановление заметок, ручные теги, автотеги, избранное, закрепление, шаблоны, версии, вложения, привязка файлов и временные ссылки;
- `notes.create` поддерживает вложенное дерево через `parentId`: Notes AI должен создавать подзаметку внутри выбранной/найденной заметки, если пользователь просит создать заметку внутри, ниже, под текущей заметкой или в подзаметке. Родительская заметка при этом остается обычной заметкой с текстом и одновременно может иметь дочерние элементы;
- для массовых команд по дереву есть `notes.createNestedBatch`: Notes AI может создать повторяемые дочерние заметки во всех активных заметках, в списке найденных родителей или в последних созданных заметках с указанными именами, а затем создать заданное количество вложенных заметок внутри каждой новой дочерней. Для режима “во всех существующих заметках” используется снимок дерева до batch-операции; для продолжения предыдущего batch вида “внутри каждой из новых двух заметок” используется `recentNamedNotes` с `parentNames` и `expectedParentCount`;
- через `attachments.attachToNote` Notes AI может привязать существующий файл аккаунта к заметке, перепривязать его или отвязать от заметок;
- через `admin.users.list` и `admin.stats.read` Notes AI может читать список пользователей и статистику только если текущий пользователь имеет роль `admin`;
- `notes.semanticSearch` ищет заметки по смыслу через embeddings текущего OpenAI-compatible provider. Backend кэширует в SQLite векторы до 300 последних активных заметок пользователя, учитывает настройку доступа к секретам и при ошибке embeddings-provider откатывается на обычный текстовый поиск;
- developer prompt подробно описывает Notes AI доступные API-инструменты, правила поиска/чтения/редактирования, формат `contentHtml/contentText`, code block HTML и поля данных;
- `notes.read` возвращает модели текст заметки, теги и дату обновления, чтобы она могла отвечать по содержимому, а не только видеть `id/name`;
- Notes AI работает по LLM-first схеме: сначала выбранная модель получает developer prompt, текущую заметку и запрос пользователя, а затем сама выбирает нужный tool-call;
- выбранная заметка передается в AI-запрос как `currentNote`, поэтому команды “измени текущую заметку” и “напиши текст в уже созданной заметке” могут превратиться в карточку редактирования конкретной заметки;
- вместе с `currentNote` в developer prompt передается текстовый и HTML-снимок текущей заметки, чтобы Notes AI понимал, что уже открыто и что именно нужно менять;
- текущая заметка в developer prompt передается как `noteId=<id>`, чтобы действия удаления, изменения, тегов, версий и ссылок использовали единый payload `noteId`;
- в `currentNote` уходит актуальный черновик редактора, а не только последняя сохраненная версия заметки, поэтому Notes AI видит недавно набранный текст до ручного сохранения;
- для команд с логином и паролем Notes AI добавляет в текущую заметку поля данных редактора, а не обычный текст;
- команды вида “перенеси данные в секретные поля” не парсятся на backend: модель сама читает `currentNote`, извлекает значения из текста и формирует `notes.update` с правильными `data-value` в полях данных;
- в шапке чата компактно показана реальная выбранная модель и примерная занятость контекста `использовано / лимит`; длинные значения скрываются троеточием с общей tooltip-подсказкой, при наведении отображается остаток;
- лимит контекста пересчитывается при смене модели по локальной таблице семейств моделей; выбранная модель сохраняется в настройках пользователя, а точный context window provider обычно не возвращает через `/models`;
- в настройках Notes AI есть отдельное разрешение чтения секретных полей. По умолчанию оно выключено: password/token/secret значения маскируются перед отправкой `currentNote` и readonly tool-результатов в модель;
- есть дневные лимиты на количество AI-запросов и token budget. Если лимит пустой, ограничение не применяется; фактическое использование за сегодня показывается в настройках Notes AI;
- в настройках Notes AI есть вкладка статистики: текущий пользователь видит месячные tokens, известную сумму в долларах и разбивку по использованным моделям; если цена модели неизвестна, показывается `?` и считается только известная часть суммы;
- админская статистика показывает месячные расходы Notes AI по каждому пользователю с разбивкой по моделям и tokens;
- в админке добавлена вкладка `Интеграции` для глобальных Telegram/VK ботов: включение, webhook/callback URL, encrypted token/secret поля, проверка подключения, политика секретов и подтверждений; webhook URL валидируется как `https://`, может автозаполняться текущим адресом приложения и provider-path, secret можно сгенерировать из UI; мини-инструкция доступна в tooltip-иконке перед названием Telegram/VK и подробно описана в `docs/bot_setup.md`;
- в настройках Notes AI есть пользовательский блок Telegram/VK: включение бота для аккаунта, единое выпадающее меню `Доступы` с группами `Режим`, `Данные`, `Действия`, доступом к секретным значениям полей данных и матрицей прав по типам действий; статус привязки показывается компактным индикатором без текстового `не привязан`, а весь provider-блок раскрывает состояние включения и привязки через общий tooltip;
- Telegram/VK runtime принимает webhook-сообщения, привязывает внешний аккаунт по одноразовому коду формата `XXXX-XXXX-XXXX-XXXX-XXXX`, передает текст в существующий Notes AI pipeline и отвечает обратно в мессенджер;
- Telegram/VK runtime принимает голосовые сообщения до 25 MB: аудио скачивается только в память, распознается через выбранный AI provider пользователя и передается в Notes AI как обычная команда; модель распознавания задается env `AI_TRANSCRIPTION_MODEL`, по умолчанию `whisper-1`;
- при генерации нового bot-кода старые коды пользователя для выбранного provider удаляются; после успешной привязки код удаляется; по клику на уже созданный код frontend копирует его в буфер обмена;
- Telegram/VK bot-runtime передает модели только разрешенные tools: чтение заметок, правка, удаление, теги, шаблоны, версии, файлы и публичные ссылки включаются отдельными permission-флагами;
- Для Telegram/VK ботов есть раздельные дневные лимиты: общий лимит сообщений, лимит readonly-tool вызовов и лимит mutation-действий. Лимиты можно задать глобально в админке и переопределить в личных bot-настройках;
- если модель возвращает mutation-действие из Telegram/VK, бот требует `accessMode: write` и соответствующий permission-флаг; при включенном подтверждении действие хранится как pending action 10 минут и выполняется по команде `подтвердить` или `подтвердить <id>`;
- перед выполнением pending-действия backend повторно проверяет актуальную матрицу прав, поэтому выключенное после preview право блокирует выполнение;
- bot runtime использует более строгую политику секретов: полные secret/password/token значения попадут в модель только если это разрешено и в глобальных настройках бота, и в пользовательских настройках бота;
- одиночные ответы `да`, `ок`, `yes` не выполняют AI-действие: при включенном подтверждении мутаций подтверждение идет только кнопкой в карточке действия;
- пустые `notes.update` без имени или содержимого backend отклоняет, чтобы модель не могла обновить только дату изменения;
- readonly и mutation tool-вызовы Notes AI дополнительно пишутся в `ai_audit_logs` без сырого payload и без секретных значений;
- chat-использование пишется в `ai_usage_logs` с provider, model, input/output tokens;
- мутации выполняются после подтверждения пользователя или сразу, если пользователь выключил подтверждение действий в настройках Notes AI; при ошибке подготовки tool-call или автоматического выполнения чат возвращает понятный текст ошибки вместо падения всего `/api/ai/chat`;
- после выполнения действия UI обновляет дерево заметок, открывает созданную/измененную заметку и явно перезагружает ее содержимое, даже если эта заметка уже была выбрана;
- после AI-удаления UI сверяет текущий выбор с новым деревом и очищает редактор, если выбранная заметка исчезла, чтобы новые заметки не создавались внутри удаленного `parentId`;
- запись важных AI-событий в историю действий.
- командная палитра `Ctrl+Shift+P` открывает быстрый поиск по действиям приложения: Notes AI, настройки AI, создание и сохранение заметки, поиск, шаблоны, корзина, ссылки, файлы, тема, язык, sidebar и админка.

Ограничения текущего этапа:

- чтение secret/password/token полей моделью разрешается только отдельной настройкой пользователя;
- Telegram/VK runtime работает как MVP для текстовых сообщений; вложения через мессенджеры пока не реализованы.

API key:

- полный ключ нельзя посмотреть после сохранения;
- если ключ потерян, его нужно создать заново у провайдера и заменить в настройках;
- удаление ключа очищает зашифрованное значение и маску.

## Редактор

Редактор построен на Tiptap.

Режимы:

- `Просмотр` - форматированный визуальный режим;
- `Редактирование` - режим изменения содержимого.

Toolbar группирует:

- режим просмотра/редактирования;
- формат текста;
- списки и блоки;
- вставки;
- undo/redo.

Ошибки редактора показываются через toast-alerting, а не через отдельные error-блоки.

## Code Block

Code block поддерживает:

- подсветку синтаксиса через lowlight;
- auto-detect, если язык не выбран или грамматики нет;
- компактный dropdown языка внутри блока;
- кнопку форматирования внутри блока;
- нумерацию строк;
- светлый вид в светлой теме и темный вид в темной теме.

Языки:

## Ссылки

- `Ctrl+K` или иконка ссылки открывает кастомную модалку.
- Если текст выделен, ссылка применяется к выделению.
- Если выделения нет, вставляется ссылка с текстом из поля.
- В режиме просмотра ссылки кликабельны.
- В режиме редактирования при наведении показывается tooltip с URL.

## Поля Данных И Секреты

Редактор поддерживает atom-node `Поле данных`. Старые отдельные кнопки `Копи-поле` и `Секретное поле` удалены полностью: в toolbar осталась одна кнопка `Поле данных`, которая вставляет поле с типом `Текст` по умолчанию. Секретный режим включается выбором типа `Пароль`, `Секрет` или `Токен` внутри самого поля.

Типы:

- `Текст`;
- `Логин`;
- `Пароль`;
- `Секрет`;
- `Токен`;
- `URL`.

Поведение:

- значение можно копировать кнопкой;
- тип поля выбирается через компактное icon-menu;
- при смене типа поля данных подпись автоматически меняется на выбранный тип, если подпись еще не была вручную кастомизирована;
- URL-поле в режиме просмотра отображается как кликабельная безопасная ссылка;
- в режиме просмотра длинные подписи и несекретные значения обрезаются троеточием и раскрываются через кастомный tooltip;
- для `Пароль`, `Секрет`, `Токен` значение маскируется символами `*` в визуальном режиме;
- password/token/secret значения не раскрываются tooltip и остаются только визуально замаскированными;
- пароль можно сгенерировать кнопкой рядом с полем;
- исходное значение перед сохранением шифруется на backend для secret/password/token полей и расшифровывается только при чтении владельцем заметки.

## Инструменты Заметки

Инструменты заметки разделены между toolbar редактора и компактным меню в шапке заметки.

- Название заметки в шапке обрезается троеточием, если не помещается.
- Иконки избранного, закрепления и тегов отображаются компактно перед датой обновления, а не перед названием заметки.
- Рядом с названием показываются только активные индикаторы: избранное, закрепление и наличие тегов.
- Если активных индикаторов нет, перед названием не резервируется пустое место, поэтому название и дата идут по одной левой линии.
- При наведении на индикатор тегов показывается компактный список тегов текущей заметки.
- Горячие клавиши находятся третьей кнопкой в группе `Просмотр / Редактирование` toolbar редактора.
- В меню шапки находятся избранное, закрепление, сохранение, удаление и управление тегами.
- Основные действия в меню шапки отображаются одинаковыми icon-кнопками без текстовых подписей: избранное и закрепление слева, сохранение и удаление справа.
- Теги глобальные для пользователя: сначала тег создается в меню шапки, затем выбирается для одной или нескольких заметок.
- Назначение тегов заметке выполняется выбором из существующего глобального списка; локальное создание тегов прямо в записи отключено.
- В меню шапки есть компактная строка поиска по тегам, отдельная кнопка добавления и список всех созданных тегов с inline-редактированием и удалением.
- Блок основных действий в меню шапки визуально отделен от поиска тегов тонкой линией и отступом.
- В списке тегов вся строка тега кликабельна для назначения заметке, кроме кнопок редактирования/удаления и активного поля ввода.
- Наведение подсвечивает всю строку тега, но не срабатывает при наведении на служебные кнопки или во время редактирования имени.
- Кнопка добавления создает пустую строку вверху списка, фокусирует ее и прокручивает список к началу.
- Если новая строка тега остается пустой после потери фокуса, она удаляется; если имя заполнено, тег сохраняется.
- Имя тега при вводе и создании приводится к нижнему регистру.
- Текст в строке поиска приводится к нижнему регистру и фильтрует глобальные теги.
- Глобальные теги в меню отсортированы по алфавиту; несохраненный новый тег всегда отображается сверху.
- Список тегов в меню шапки показывает до пяти строк без прокрутки, остальные теги доступны через внутренний scroll.
- Удаление глобального тега снимает его со всех заметок текущего пользователя.
- В sidebar есть быстрые фильтры: все заметки и избранные.
- Закрепленные заметки не являются отдельным фильтром: они дополнительно отображаются плоским списком быстрых ссылок вверху обычного дерева `Все заметки`.
- Основное дерево при закреплении не меняет структуру и порядок: заметка остается в своей папке вместе с дочерними элементами.
- Избранные и закрепленные заметки получают маленькие индикаторы в строке дерева.
- Избранное отображается плоским списком только из избранных заметок, без родительского дерева.
- Теги выбираются через компактную кнопку в sidebar: в самой кнопке отображаются только иконка и число глобальных тегов, выбранный тег не подставляется в кнопку.
- Если тегов нет, кнопка тегов отображается, но отключена.
- Выбор тега показывает плоский список заметок с этим тегом, без родительского дерева.
- При выборе `Все заметки` или `Избранное` активный тег автоматически сбрасывается.
- Поиск в sidebar ищет по названию заметки и по тегам; поиск комбинируется с активным режимом.
- В боковом меню есть раздел `Управление заметками` между навигацией и настройками.
- В `Управление заметками` находятся `Корзина`, `Файлы аккаунта`, `Экспорт JSON` и `Импорт JSON`.
- `Экспорт JSON` скачивает файл с активными заметками, тегами, избранным, закреплением, parent-связями и пользовательскими шаблонами; заметки из корзины не включаются.
- Значения secret/password/token полей данных в JSON backup хранятся в `data-value` в зашифрованном виде `enc:v1:...`; звездочки внутри HTML - только визуальная маска для отображения и не используются для восстановления.
- `Импорт JSON` открывает системный выбор файла, валидирует структуру JSON и восстанавливает заметки, теги, избранное, закрепление и parent-связи в одной транзакции.
- Markdown export удален из UI и REST API.
- `Корзина`, `Версии`, `Шаблоны`, `Ссылки доступа` и `Вложения` открываются отдельными компактными модалками из верхнего меню редактора.
- В панели `Версии` одновременно видно до 5 элементов, при большем количестве включается внутренний скролл. Backend хранит не больше 80 версий на заметку, удаляет самые старые при превышении лимита и очищает версии при удалении заметки.
- Строки версий выровнены по ширине панели: название и дата находятся слева, кнопка восстановления закреплена справа в отдельной компактной зоне и не выходит за край блока.
- Строки корзины используют отдельную устойчивую раскладку: название обрезается троеточием, кнопки восстановления и удаления закреплены справа и не выходят за границы панели.
- Во вложениях пустое состояние отображается в одну строку: иконка скрепки и текст `Пусто`.
- Файлы принадлежат аккаунту, а привязка к заметке опциональная. Удаление заметки не удаляет физические файлы: при окончательном удалении заметки вложения отвязываются и остаются в `Файлах аккаунта`.
- `Файлы аккаунта` открывают тот же файловый менеджер, но показывают все файлы текущего пользователя, включая файлы без заметки и файлы, которые были отвязаны после удаления заметки.
- В глобальном файловом менеджере у каждого файла есть компактный выбор заметки. Через него файл можно привязать к существующей заметке, перепривязать к другой или отвязать.
- Загрузка вложений в заметке идет через note-scoped endpoint `POST /api/notes/:id/attachments`; загрузка из глобального файлового менеджера идет через `POST /api/attachments` без обязательного `noteId`.
- Окно вложений работает как полноширинный файловый менеджер с равными отступами от краев экрана: файлы отображаются плитками, изображения получают миниатюры, имя можно переименовать прямо в карточке, а просмотр открывается плавающей панелью только после выбора конкретного файла.
- Плитки вложений не используют тяжелые рамки и подложки: отображается файл, имя, размер и компактное меню `...` в правом верхнем углу с действиями открыть, открыть в браузере, переименовать, скачать и удалить. Меню рендерится поверх списка, не обрезается скролл-контейнером, закрывается по клику вне меню, а обрезанные пункты показывают полный текст через tooltip.
- Панель просмотра можно перемещать за шапку и растягивать за стороны или углы; координаты и размер ограничены границами окна вложений.
- Открытый файл в панели просмотра не участвует в native browser drag-and-drop: перетаскивание по области файла двигает preview-панель, а не создает повторную загрузку файла. Кнопки скачивания, закрытия, media controls и resize-зоны остаются обычными управляющими элементами.
- Панель просмотра без лишней внутренней рамки: контент занимает всю область, а кнопки скачивания и закрытия наложены поверх предпросмотра прозрачными иконками.
- Tooltip-подсказки рассчитывают свободное место по всем сторонам: по умолчанию открываются сверху или снизу и дополнительно сдвигаются по горизонтали, если длинный текст упирается в край экрана.
- Поддерживается выделение как в файловом менеджере: обычный клик выбирает один файл, `Ctrl`/`Cmd` добавляет или снимает точечный выбор, `Shift` выделяет диапазон.
- При выделении одного или нескольких файлов в верхней панели появляется отдельная группа быстрых действий: скачать выбранные ZIP-архивом, удалить выбранные и снять выделение.
- Файлы можно загружать через системный выбор или drag-and-drop; загрузка принимает один или несколько файлов за раз.
- Поиск во вложениях фильтрует по имени файла и расширению.
- ZIP-кнопка скачивает выбранные файлы, а если выделения нет - все вложения текущей заметки или все файлы аккаунта в глобальном режиме.
- Удаление работает для выбранных файлов; если ничего не выбрано, кнопка удаляет все вложения текущей заметки.
- Backend удаляет физические файлы из `UPLOAD_DIR` при удалении одного вложения и удалении пользователя администратором. Окончательное удаление заметки только отвязывает файлы от заметки.
- Просмотр поддерживает изображения, PDF, текстовые файлы, видео и аудио. Для неподдерживаемых типов показывается сообщение и кнопка скачивания, без автоматического скачивания.
- Ссылки доступа создают публичный frontend URL `/share/<token>`, который открывает отдельную страницу только с компактной шапкой и preview заметки без редактора, бокового меню и панелей управления.
- Публичная страница рендерит контент через тот же read-only Tiptap viewer, что и основной экран просмотра заметки: ссылки открываются, поля данных `text/login/url` сохраняют значения и копирование даже у старых записей с `data-secret="true"`, длинные label/value в полях данных обрезаются троеточием с custom tooltip, а password/credential/token fields маскируются и не раскрывают полное значение в tooltip при `includeSecrets=false`.
- В панели ссылок доступа есть переключатель `Показывать секреты`; он включен по умолчанию, поэтому новые публичные ссылки сохраняют значения secret/password/token для кнопки копирования, но визуально показывают их замаскированными.
- В панели ссылок доступа есть переключатель `Одноразовая ссылка`. Такая ссылка открывается один раз, после успешного просмотра backend увеличивает счетчик доступа и сразу отзывает ссылку для следующих открытий.
- На публичной странице цветом выделяется вся карточка заметки целиком, а не отдельная внутренняя область контента.
- Активные ссылки доступа в списке отображаются кликабельной строкой и отдельной кнопкой копирования; при отзыве ссылка сразу удаляется из списка и базы.
- Все панели используют существующие custom modal, tooltip, icon button и toast.

## Безопасность Данных

- Секретные значения полей данных в заметках шифруются AES-256-GCM ключом `SECRET_ENCRYPTION_KEY`.
- Для восстановления секретных значений из JSON backup на другой установке нужен тот же `SECRET_ENCRYPTION_KEY`; без него зашифрованные `data-value` не расшифруются.
- Временные публичные ссылки хранят hash токена для проверки и публичный URL для повторного копирования активной ссылки.
- По умолчанию публичная ссылка скрывает значения секретных полей данных.
- Все операции с заметками, тегами, версиями, корзиной, шаблонами, вложениями и ссылками scoped по текущему `user_id`.
- AI-настройки, список моделей и Telegram/VK bot-настройки scoped по текущему `user_id`.
- AI API key хранится отдельно от секретных полей заметок и шифруется ключом `AI_CREDENTIALS_ENCRYPTION_KEY`.

## Админка

Раздел называется `Панель администратора`.

Админка загружается отдельным frontend chunk только при открытии раздела. Для пользователя поведение не меняется, но старт приложения остается легче.

Вкладки:

- `Пользователи`;
- `История`;
- `Статистика`.

### Пользователи

- Поиск по имени пользователя.
- Создание пользователя через кастомную модалку.
- Логин существующего пользователя не редактируется.
- Роль меняется через кастомный dropdown.
- Пароль меняется через password input с `autocomplete="new-password"`; форма содержит скрытое username-поле текущего пользователя для browser accessibility/autocomplete проверок.
- Сохранение и удаление выполнены icon buttons.
- Удалить себя нельзя.

### История

История отображается таблицей:

- пользователь;
- дата;
- действие;
- инициатор;
- цель.

В заголовках колонок есть фильтры. Фильтры рендерятся через portal и не обрезаются scroll-контейнерами. Сортировка даты выполняется из заголовка таблицы.

### Статистика

Статистика показывает:

- всего пользователей;
- активных пользователей за сегодня;
- нагрузку за последние 24 часа;
- занятый объем файлового хранилища;
- количество файлов и файлов без привязки к заметке;
- количество активных публичных ссылок;
- график активности с переключением периода: 1 день, 7 дней, месяц, год;
- подписи точек графика строятся по фактическому bucket из API: час, день или месяц;
- для плотных периодов график сохраняет минимальную ширину колонок и прокручивается горизонтально, чтобы подписи не обрезались сразу после выбора месяца;
- блок `Объем данных` с заметками, событиями, файлами, версиями и активными ссылками;
- память по файлам: средний размер, самый большой файл, заметки с файлами и объем отвязанных файлов;
- распределение файлов по типам;
- блок LLM: диалоги за 24 часа, подтвержденные AI-действия за 24 часа, активные AI-пользователи, сколько пользователей включили Notes AI, сколько пользователей выбрали модель, количество провайдеров, активных/устаревших моделей и последняя синхронизация;
- топ выбранных LLM-моделей по количеству пользователей;
- топ пользователей по занятому файловому объему и активности.

## UI И Темы

- Светлая и темная темы.
- Интерфейс использует системный стек `Aptos` / `Segoe UI Variable` / `Segoe UI`, без внешних font-зависимостей.
- Основной фон светлой темы спокойный холодный почти-белый, без насыщенного голубого полотна.
- Основной фон темной темы глубокий индиго-графитовый, без розово-циановых фоновых слоев.
- Sidebar и основной рабочий блок имеют плотную тонкую тень справа и снизу; цвет тени близок к фону текущей темы.
- В светлой теме декоративные кубы и частицы используют более контрастные синие линии и плотность заливки, чтобы оставаться читаемыми на светлом фоне.
- Кастомные dropdown, tooltip, modal, toast.
- Native `alert`, `prompt`, `confirm` не используются.
- Иконки берутся из `lucide-react`.
- Tooltip единый для всего сайта и отображается поверх окон, включая меню заметки и вложенные popup-панели.
- Toast-alerts находятся в правом нижнем углу, имеют компактный размер, нижнюю полоску времени жизни без цветного бокового бордера и ставят таймер на паузу при наведении. Одновременно отображается не больше трех уведомлений; при появлении нового лишнее уведомление плавно закрывается.
- Скроллы тонкие и малозаметные.
- Горизонтальные панели без вертикального scroll, включая toolbar редактора и вкладки админки, прокручиваются обычным колесом без `Shift` даже при наведении на кнопки/иконки; обработка wheel подключена native listener с `passive: false`, чтобы браузер не ругался на отмену стандартной прокрутки. Если у области есть оба направления scroll, колесо без `Shift` оставляет вертикальную прокрутку.
- Текст в ограниченных элементах обрезается троеточием; полный текст показывается в tooltip только при фактическом ellipsis.
- В документации изображения лежат только в `docs/images`.
