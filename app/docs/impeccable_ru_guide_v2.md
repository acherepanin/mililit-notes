# Impeccable: краткий справочник

> Impeccable: скилл для UI/UX и фронтенд-интерфейсов. Он помогает спланировать, собрать, улучшить, проверить и довести интерфейс до продакшена.

---

## 1. Быстрый старт

Первичная настройка проекта:

```text
$impeccable init
```

Команда создаёт или обновляет контекст:

```text
PRODUCT.md  - продукт, аудитория, цели, характер, анти-референсы
DESIGN.md   - дизайн-система, токены, компоненты, визуальные правила
.impeccable/live/config.json - настройка live-режима, если в проекте есть фронтенд
```

Если нужно отдельно зафиксировать дизайн-систему из уже существующего кода:

```text
$impeccable document
```

Старый `teach` больше не нужен. Если встретишь его в старых промптах, используй `init`.

---

## 2. Формат команды

```text
$impeccable [команда] [цель или объект работы]
```

Примеры:

```text
$impeccable polish экран настроек AI
$impeccable audit app/front/src/features/notes
$impeccable shape новый лендинг тарифов
```

Если написать только `$impeccable`, скилл предложит 2-3 полезных следующих шага по текущему проекту.

---

## 3. Актуальные команды

### Сборка и контекст

| Команда | Когда использовать |
|---|---|
| `init` | Настроить проектный контекст: `PRODUCT.md`, `DESIGN.md`, live config. |
| `document` | Сгенерировать или обновить `DESIGN.md` по текущему коду. |
| `shape` | Сначала спланировать UX/UI без внедрения. |
| `craft` | Спланировать и реализовать фичу, экран или компонент end-to-end. |
| `extract` | Вынести повторяющиеся паттерны в токены, компоненты или дизайн-систему. |

### Проверка

| Команда | Когда использовать |
|---|---|
| `critique` | Дизайн-ревью: проблемы, приоритеты, оценка, рекомендации. |
| `audit` | Техническая проверка UI: доступность, адаптив, состояния, производительность. |

### Улучшение готового интерфейса

| Команда | Когда использовать |
|---|---|
| `polish` | Финально улучшить готовый интерфейс перед релизом. |
| `bolder` | Сделать дизайн смелее и выразительнее. |
| `quieter` | Уменьшить визуальный шум. |
| `distill` | Упростить интерфейс и оставить главное. |
| `harden` | Довести до продакшена: ошибки, пустые состояния, i18n, длинные тексты. |
| `onboard` | Спроектировать онбординг, первый запуск, пустые состояния. |

### Точечные слои

| Команда | Когда использовать |
|---|---|
| `animate` | Добавить осмысленную motion-систему и микровзаимодействия. |
| `colorize` | Улучшить цвет, контраст, акценты, состояния. |
| `typeset` | Улучшить типографику и читаемость. |
| `layout` | Исправить сетку, отступы, ритм, выравнивание. |
| `delight` | Добавить запоминающиеся, но уместные детали. |
| `overdrive` | Сильно усилить визуальный эффект, когда нужен вау-режим. |
| `clarify` | Улучшить UX-тексты, подписи, ошибки, пустые состояния. |
| `adapt` | Адаптировать интерфейс под экраны и устройства. |
| `optimize` | Найти и исправить проблемы UI-производительности. |

### Интерактивный режим и шорткаты

| Команда | Когда использовать |
|---|---|
| `live` | Выбрать элемент в браузере, получить варианты и применить один из них. |
| `pin <command>` | Создать короткую команду, например `$polish`. |
| `unpin <command>` | Удалить короткую команду. |

## 4. Как выбрать команду

| Хочу | Команда |
|---|---|
| Новый экран или фича | `shape` → `craft` |
| Большой редизайн | `shape` → `craft` |
| Аккуратно улучшить готовый UI | `critique` → `polish` |
| Проверить перед релизом | `audit` → `harden` |
| Только отступы и сетку | `layout` |
| Только типографику | `typeset` |
| Только цвета | `colorize` |
| Упростить | `distill` |
| Убрать визуальный шум | `quieter` |
| Сделать смелее | `bolder` |
| Добавить анимации | `animate` |
| Улучшить тексты | `clarify` |
| Проверить мобильный вид | `adapt` |
| Ускорить UI | `optimize` |
| Настроить дизайн-систему | `document` → `extract` |
| Быстро попробовать варианты в браузере | `live` |

## 5. Примеры промптов

### Настроить проект

```text
$impeccable init

Проект: приложение заметок с редактором, админкой и AI-инструментами.
Регистр: продуктовый UI.
Характер: спокойный, современный, понятный широкой аудитории.
Анти-референсы: не делать типовой AI/SaaS с фиолетовыми градиентами и неоном.
Доступность: WCAG AA, клавиатура, фокус, reduced motion.
```

### Спланировать без кода

```text
$impeccable shape редизайн экрана настроек AI

Цель: сделать экран понятнее и спокойнее.
Сначала предложи 3 направления.
Укажи компромиссы и риски.
Пока не редактируй файлы.
```

### Реализовать фичу

```text
$impeccable craft панель быстрых действий для заметки

Цель: добавить компактную панель действий рядом с редактором.
Используй существующие IconButton, Tooltip, Modal и токены из DESIGN.md.
Нужны состояния загрузки, ошибки, disabled и мобильный вид.
Не вводи новую библиотеку компонентов.
```

### Аккуратно улучшить текущий экран

```text
$impeccable polish app/front/src/features/ai/AiAssistant.tsx

Цель: улучшить читаемость, отступы, состояния и адаптив.
Сохрани текущую структуру и бизнес-логику.
Используй существующие компоненты и CSS-токены.
Изменения должны быть небольшими и контролируемыми.
```

### Провести ревью

```text
$impeccable critique экран админской статистики

Проверь:
- понятность и визуальную иерархию
- перегруз информацией
- состояния пустых данных
- мобильный вид
- соответствие PRODUCT.md и DESIGN.md

Пока ничего не внедряй.
```

### Проверить перед релизом

```text
$impeccable audit app/front/src/features/notes

Проверь:
- доступность и фокус
- управление с клавиатуры
- длинные русские строки
- ошибки и пустые состояния
- адаптив
- риски производительности
```

### Довести до продакшена

```text
$impeccable harden экран публичной ссылки

Подготовь интерфейс к релизу.
Проверь loading, error, empty, expired link, long content, mobile, i18n.
Не меняй визуальный язык без необходимости.
```

### Упростить перегруженный UI

```text
$impeccable distill окно настроек AI

Цель: убрать лишнее и оставить главное.
Сохрани все обязательные настройки.
Сгруппируй поля понятнее.
Не прячь опасные действия без явного состояния или подтверждения.
```

### Сделать спокойнее

```text
$impeccable quieter админ-панель интеграций

Цель: уменьшить визуальный шум.
Убери лишние акценты, тяжёлые рамки и конкурирующие состояния.
Сохрани понятные статусы Telegram/VK и доступность.
```

### Сделать смелее

```text
$impeccable bolder лендинг продукта

Цель: сделать первый экран сильнее и дороже.
Можно усилить композицию, типографику, motion и визуальный ритм.
Нельзя уходить в типовой AI/SaaS, фиолетовые градиенты, орбы и неон.
```

### Улучшить тексты

```text
$impeccable clarify ошибки входа и пустые состояния заметок

Цель: сделать тексты понятнее.
Пиши коротко, по-русски и по-английски.
Кнопки должны говорить действие: "Создать заметку", "Повторить вход".
```

### Интерактивно подобрать вариант

```text
$impeccable live
```

Открой приложение, выбери элемент в браузере, задай русскую правку, например:

```text
Сделай это состояние спокойнее: меньше акцента, больше читаемости, без изменения структуры.
```

## 6. Универсальный шаблон

```text
$impeccable [команда] [экран/компонент/фича]

Контекст:
[что это и где находится]

Цель:
[какой результат нужен]

Сохранить:
- [что нельзя ломать]
- [какую логику оставить]

Можно:
- [что разрешено менять]

Запрещено:
- [чего точно не делать]

Правила:
- Следуй PRODUCT.md и DESIGN.md.
- Сначала используй существующие компоненты и токены.
- Учитывай RU/EN, доступность и reduced motion.
- Не вводи новый визуальный язык без явного запроса.

Результат:
[план / код / ревью / небольшой polish / полный редизайн]
```

---

## 7. Главное правило

Команда задаёт тип работы. Твой текст задаёт цель, ограничения и степень свободы.

Короткий рабочий промпт:

```text
$impeccable polish [экран]

Цель: улучшить интерфейс без редизайна с нуля.
Сохрани текущий пользовательский сценарий.
Используй существующие компоненты и токены.
Улучши отступы, типографику, иерархию, состояния и адаптив.
После изменений кратко объясни, что поменялось.
```
