# UI

Документ фиксирует существующие UI-компоненты и правила их переиспользования. Если нужен новый элемент интерфейса, сначала проверить этот список. Если подходящего компонента нет, создать кастомный компонент в текущем стиле приложения, а не использовать native/browser UI.

## Общие Правила

- Не использовать native `alert`, `prompt`, `confirm`; ошибки и статусы показывать через toast-alerting.
- Не использовать native `title` для подсказок. Для hover/focus подсказок использовать общий `Tooltip` или `TooltipText`.
- Не использовать обычный browser select, если нужен выпадающий список в интерфейсе приложения. Использовать `CustomSelect` или создать кастомный компонент с теми же правилами портального отображения.
- Все icon buttons должны идти через `IconButton`, иметь локализованный `label` и иконку из `lucide-react`, если подходящая есть.
- Если текст может не поместиться, скрывать его троеточием и показывать полный текст через кастомную подсказку.
- Все placeholder-тексты должны начинаться с заглавной буквы. По умолчанию placeholder использует общий размер `--font-ui`; компактный размер `--font-placeholder` использовать только внутри настроек Notes AI.
- Popup, меню и dropdown должны отображаться поверх родителя и не обрезаться контейнерами.
- Новый UI должен поддерживать RU/EN, light/dark темы и общие размеры шрифтов.

## Компоненты

### `Tooltip`

Файл: `front/src/components/Tooltip.tsx`.

Назначение:

- общий кастомный tooltip через portal в `document.body`;
- позиционируется над элементом, если сверху хватает места, иначе снизу;
- сдвигается по горизонтали, чтобы не выходить за границы экрана;
- работает по hover и focus;
- заменяет native `title`.

Использовать:

- для иконок, компактных индикаторов, счетчиков, элементов без видимого текста;
- когда подсказка должна показываться всегда при наведении;
- для сложных составных элементов, где tooltip нужен на весь блок.

Не использовать:

- если нужно показывать подсказку только при обрезанном тексте, для этого есть `TooltipText`.

### `TooltipText`

Файл: `front/src/components/TooltipText.tsx`.

Назначение:

- оборачивает текст;
- применяет ellipsis;
- автоматически показывает `Tooltip` только если текст реально обрезан;
- отслеживает изменение размеров через `ResizeObserver`.

Использовать:

- названия заметок, тегов, моделей, файлов, пользователей;
- значения в таблицах и меню;
- любые строки, где возможны троеточия.

### `IconButton`

Файл: `front/src/components/IconButton.tsx`.

Назначение:

- единый вид кнопок с иконками;
- локализованный label/tooltip;
- поддержка variants и disabled-состояний;
- центрирование иконки внутри кликабельной области.

Использовать:

- все кнопки действий;
- кнопки меню, сохранения, удаления, копирования, открытия, настроек.

### `CustomSelect`

Файл: `front/src/components/CustomSelect.tsx`.

Назначение:

- кастомный select/dropdown;
- открывается вверх или вниз в зависимости от свободного места;
- не должен обрезаться родительскими контейнерами;
- текст значений должен сокращаться троеточием с подсказкой.

Использовать:

- выбор роли, языка, темы, фильтров, форматов, типов.

### `Modal`

Файл: `front/src/components/Modal.tsx`.

Назначение:

- общий кастомный modal/popup;
- используется вместо browser dialog;
- закрытие, заголовок и действия оформляются в стиле приложения.

Использовать:

- подтверждения;
- настройки;
- большие панели управления.

### `ToastHost` И `useToasts`

Файлы:

- `front/src/components/ToastHost.tsx`;
- `front/src/components/useToasts.ts`.

Назначение:

- общий alerting;
- не больше трех активных сообщений;
- время жизни с progress bar;
- пауза таймера при hover.

Использовать:

- ошибки API;
- результат сохранения;
- предупреждения;
- статусы операций.

## Notes AI UI

AI-чат использует те же правила:

- в шапке чата модель и контекст показываются компактно;
- версия модели должна быть визуально прижата к короткой полоске контекста, а статусный блок выровнен по центру шапки;
- полные значения показывать только через кастомный `Tooltip`;
- в шапке чата не должно быть отдельных вкладок чата/статистики; статистика открывается из окна настроек Notes AI;
- остановка активного AI-запроса должна заменять кнопку отправки в composer, пока модель думает над ответом;
- очистка диалога должна быть icon-only `IconButton` с кастомным tooltip, без native `title`;
- не использовать native `title`;
- для выбора списка провайдеров использовать `CustomSelect`, а не сетку кнопок или обычный browser select; ручные поля provider/base URL показывать только для варианта `Свой`/`Custom`;
- при выборе сохраненного провайдера UI должен подтягивать его `apiKeyHint` и выбранную модель через `/api/ai/settings`, не показывая полный API key;
- список провайдеров, API key, дневные лимиты, доступ к секретам и подтверждение действий должны быть объединены в одну компактную группу настроек Notes AI. Provider-select и API key располагать в одну строку, лимиты делать узкими числовыми полями, доступ к секретам и подтверждение действий - icon-кнопками с rich tooltip. Не использовать native checkbox; переключатель должен быть кастомной кнопкой в текущем стиле.
- счетчик `usageToday` показывать компактной строкой без заголовка `Сегодня` и без progress-полосок, под полями лимитов, растянутым на всю ширину группы;
- кнопка очистки API key должна быть простой иконкой корзины без фоновой плитки;
- окно настроек Notes AI должно иметь внутренний скролл, а смысловые группы настроек - легкое визуальное разделение с увеличенным вертикальным отступом между группами;
- текстовые поля внутри настроек Notes AI оформлять единообразно: иконка внутри строки слева, затем ввод; не смешивать поля с иконками и без иконок в одной группе;
- список моделей в настройках Notes AI должен занимать оставшуюся высоту окна и скроллиться внутри себя, без пустой нижней области;
- длинные названия моделей и счетчики должны обрезаться троеточием без вертикального подрезания букв.
- tooltip цены модели должен быть rich-tooltip через общий `Tooltip`, локализованный RU/EN, с расчетом за 1 миллион tokens. Неизвестные цены показывать знаком `?`, а не `0`.
- поля API key/password в настройках должны находиться внутри настоящего `form`; для browser/password-manager compatibility добавлять скрытое `username`-поле через `.sr-only`, чтобы не получать DOM-предупреждения браузера.
- Пользовательские настройки Telegram/VK-ботов находятся внутри этого же окна настроек Notes AI отдельной компактной группой. Использовать существующие `TooltipText`, icon-кнопки и кастомные dropdown/toggle-кнопки в стиле AI-настроек; не добавлять native select/checkbox/dialog.
- Код привязки бота показывать компактно в строке provider. Если кода еще нет, клик создает новый одноразовый код; если код уже показан, клик по нему копирует код в буфер. Длинные статусы привязки и username должны обрезаться троеточием и раскрывать полный текст через общий tooltip.
- Provider-кнопки Telegram/VK в настройках Notes AI должны быть компактнее кнопки `Доступы`, но текст `Telegram` должен помещаться без обрезки; индикатор provider-кнопки прижимать к правому краю. Поле `Доступы` занимает основную ширину строки, а код привязки остается компактным. Индикатор серый, когда бот выключен, и синий, когда бот включен. При наведении на весь блок должен открываться общий кастомный tooltip со статусами включения и привязки.
- Матрица прав Telegram/VK в настройках Notes AI находится в одном dropdown `Доступы`: внутри группируются режим работы, доступ к данным, секретные поля и действия. Выбранные пункты подсвечиваются, длинный текст обрезается троеточием и раскрывается через общий tooltip. Отдельные кнопки/иконки секретов и отдельный select режима бота не использовать.
- Все новые иконки в настройках Notes AI, bot-настройках и admin-интеграциях должны иметь кастомный `Tooltip` с коротким описанием смысла и действия. Не использовать native `title`.
- Кнопка голосового ввода в composer Notes AI должна быть обычным `IconButton` с `Tooltip`; при активном распознавании использовать отдельное состояние и не показывать browser/native подсказки.
- Строка ожидания Notes AI должна быть компактной status-капсулой без видимого текста, только с мягко анимированными точками; индикатор не должен менять размеры composer или сообщений.
- Служебные результаты AI-действий показывать отдельными status-сообщениями: успех - анимированная галочка без текста, ошибка - анимированный крестик и текст ошибки. Иконки статусов должны быть без фоновой заливки и без частиц, с еле заметной плавной анимацией. Обычные ответы, уточняющие вопросы и пояснения модели остаются текстовыми сообщениями.
- Текст результата успешного AI-действия скрыт визуально, но остается в chat history для следующего запроса модели; не фильтровать такие status-сообщения из истории.

## Command Palette UI

- Командная палитра находится в `features/app/CommandPalette.tsx` и открывается по `Ctrl+Shift+P`.
- Палитра отображается через portal поверх текущего интерфейса, закрывается по `Esc` и клику по фону.
- Поле поиска использует `autoComplete="off"` и общий стиль поисковых строк.
- Иконки команд берутся из `lucide-react`, а длинные названия и описания идут через `TooltipText`.
- Не добавлять отдельные browser prompt/dialog для команд: действие либо выполняется сразу, либо открывает существующую кастомную панель/модалку приложения.

## Admin Integrations UI

- Telegram/VK настройки находятся в админке во вкладке `Интеграции`.
- Внутри вкладки использовать компактные provider tabs, а не отдельные страницы.
- Token/secret/access token поля не показывают сохраненное значение, только безопасную маску из backend.
- Поля token/secret должны использовать `type="password"` и `autoComplete="new-password"`.
- URL поля используют `autoComplete="url"`, технические ID и confirmation code - `autoComplete="off"`.
- В форме Telegram/VK порядок ключевых полей: webhook/callback URL, secret, token, остальные provider-поля. Webhook/callback URL всегда первый, имеет tooltip после label, правую icon-кнопку автозаполнения и валидацию `https://` перед сохранением. Secret-поле имеет правую icon-кнопку генерации URL-safe секрета.
- Переключатели включения, подтверждений и секретов оформлять кастомными кнопками, не native checkbox.
- В заголовке карточки Telegram/VK перед названием provider показывать компактную tooltip-иконку через общий `Tooltip`; иконка использует мягкую зацикленную пульсацию и отключает анимацию при `prefers-reduced-motion`. Внутри tooltip кратко описывать шаги создания и настройки бота для выбранного provider.

## Forms And Inputs

- Любой JSX `<input>`, кроме `type="file"`, должен иметь явный `autoComplete`.
- Для поисков, названий заметок, тегов, технических фильтров и временных рабочих полей использовать `autoComplete="off"`.
- Для URL использовать `autoComplete="url"`, для логина `autoComplete="username"`, для текущего пароля `autoComplete="current-password"`, для нового/API key `autoComplete="new-password"`.
- В реальных формах логина/пароля задавать стабильные `name` у username/password inputs, чтобы browser diagnostics и password managers корректно распознавали поля.
- Password/API key поля держать внутри настоящего `<form>`; если форма не содержит видимый username, добавлять скрытый username input через `.sr-only`.
- В toolbar редактора должна быть одна кнопка `Поле данных`; старые отдельные кнопки `Копи-поле` и `Секретное поле` удалены и не возвращаются.
- Поля данных редактора не должны использовать `type="password"` вне формы. Для маскирования использовать обычный text input с визуальным CSS-маскированием.
- Поля данных в режиме просмотра используют text-like элементы с ellipsis и `TooltipText` для длинных label/value. Для password/token/secret значений tooltip с полным значением не показывать; в режиме редактирования оставлять обычные input без ellipsis.
- Публичная страница временной ссылки `/share/<token>` использует тот же read-only copy-field режим: `copy-field--view`, ellipsis и custom tooltip должны работать так же, как в обычном preview заметки.
- `npm run lint` на фронте запускает `lint:dom`, который падает на новых non-file `<input>` без `autoComplete`.

## Документация При Изменениях

Если добавлен новый UI-компонент или изменено поведение существующего:

- обновить этот файл;
- обновить `docs/functionality.md`, если изменилось пользовательское поведение;
- обновить стартовый prompt Notes AI, если бот должен знать о новом UI/API/tool-call или о том, что старый функционал удален.
