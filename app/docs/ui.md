# UI

Документ фиксирует существующие UI-компоненты и правила их переиспользования. Если нужен новый элемент интерфейса, сначала проверить этот список. Если подходящего компонента нет, создать кастомный компонент в текущем стиле приложения, а не использовать native/browser UI.

## Общие Правила

- Не использовать native `alert`, `prompt`, `confirm`; ошибки и статусы показывать через toast-alerting.
- Не использовать native `title` для подсказок. Для hover/focus подсказок использовать общий `Tooltip` или `TooltipText`.
- Не использовать обычный browser select, если нужен выпадающий список в интерфейсе приложения. Использовать `CustomSelect` или создать кастомный компонент с теми же правилами портального отображения.
- Все icon buttons должны идти через `IconButton`, иметь локализованный `label` и иконку из `lucide-react`, если подходящая есть.
- Если текст может не поместиться, скрывать его троеточием и показывать полный текст через кастомную подсказку.
- Popup, меню и dropdown должны отображаться поверх родителя и не обрезаться контейнерами.
- Новый UI должен поддерживать RU/EN, light/dark темы и общие размеры шрифтов.

## Компоненты

### `Tooltip`

Файл: `front/src/components/Tooltip.tsx`.

Назначение:

- общий кастомный tooltip через portal в `document.body`;
- позиционируется над элементом, если сверху хватает места, иначе снизу;
- сдвигается по горизонтали, чтобы не выходить за границы экрана;
- работает по hover и focus;
- заменяет native `title`.

Использовать:

- для иконок, компактных индикаторов, счетчиков, элементов без видимого текста;
- когда подсказка должна показываться всегда при наведении;
- для сложных составных элементов, где tooltip нужен на весь блок.

Не использовать:

- если нужно показывать подсказку только при обрезанном тексте, для этого есть `TooltipText`.

### `TooltipText`

Файл: `front/src/components/TooltipText.tsx`.

Назначение:

- оборачивает текст;
- применяет ellipsis;
- автоматически показывает `Tooltip` только если текст реально обрезан;
- отслеживает изменение размеров через `ResizeObserver`.

Использовать:

- названия заметок, тегов, моделей, файлов, пользователей;
- значения в таблицах и меню;
- любые строки, где возможны троеточия.

### `IconButton`

Файл: `front/src/components/IconButton.tsx`.

Назначение:

- единый вид кнопок с иконками;
- локализованный label/tooltip;
- поддержка variants и disabled-состояний;
- центрирование иконки внутри кликабельной области.

Использовать:

- все кнопки действий;
- кнопки меню, сохранения, удаления, копирования, открытия, настроек.

### `CustomSelect`

Файл: `front/src/components/CustomSelect.tsx`.

Назначение:

- кастомный select/dropdown;
- открывается вверх или вниз в зависимости от свободного места;
- не должен обрезаться родительскими контейнерами;
- текст значений должен сокращаться троеточием с подсказкой.

Использовать:

- выбор роли, языка, темы, фильтров, форматов, типов.

### `Modal`

Файл: `front/src/components/Modal.tsx`.

Назначение:

- общий кастомный modal/popup;
- используется вместо browser dialog;
- закрытие, заголовок и действия оформляются в стиле приложения.

Использовать:

- подтверждения;
- настройки;
- большие панели управления.

### `ToastHost` И `useToasts`

Файлы:

- `front/src/components/ToastHost.tsx`;
- `front/src/components/useToasts.ts`.

Назначение:

- общий alerting;
- не больше трех активных сообщений;
- время жизни с progress bar;
- пауза таймера при hover.

Использовать:

- ошибки API;
- результат сохранения;
- предупреждения;
- статусы операций.

## Notes AI UI

AI-чат использует те же правила:

- в шапке чата модель и контекст показываются компактно;
- полные значения показывать только через кастомный `Tooltip`;
- не использовать native `title`;
- длинные названия моделей и счетчики должны обрезаться троеточием без вертикального подрезания букв.
- поля API key/password в настройках должны находиться внутри настоящего `form`; для browser/password-manager compatibility добавлять скрытое `username`-поле через `.sr-only`, чтобы не получать DOM-предупреждения браузера.

## Forms And Inputs

- Любой JSX `<input>`, кроме `type="file"`, должен иметь явный `autoComplete`.
- Для поисков, названий заметок, тегов, технических фильтров и временных рабочих полей использовать `autoComplete="off"`.
- Для URL использовать `autoComplete="url"`, для логина `autoComplete="username"`, для текущего пароля `autoComplete="current-password"`, для нового/API key `autoComplete="new-password"`.
- В реальных формах логина/пароля задавать стабильные `name` у username/password inputs, чтобы browser diagnostics и password managers корректно распознавали поля.
- Password/API key поля держать внутри настоящего `<form>`; если форма не содержит видимый username, добавлять скрытый username input через `.sr-only`.
- Secret/copy fields редактора не должны использовать `type="password"` вне формы. Для маскирования использовать обычный text input с визуальным CSS-маскированием.
- `npm run lint` на фронте запускает `lint:dom`, который падает на новых non-file `<input>` без `autoComplete`.

## Документация При Изменениях

Если добавлен новый UI-компонент или изменено поведение существующего:

- обновить этот файл;
- обновить `docs/functionality.md`, если изменилось пользовательское поведение;
- обновить стартовый prompt Notes AI, если бот должен знать о новом UI/API/tool-call или о том, что старый функционал удален.
