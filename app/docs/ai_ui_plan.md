# План UI Для AI-Ассистента

## Цель

Добавить AI-режим как отдельный управляемый слой поверх текущего интерфейса блокнота. По умолчанию AI выключен. Пользователь сам включает его в меню, после чего получает быстрый доступ к мини-чату и настройкам моделей.

Весь AI-функционал должен быть изолирован в отдельном модуле, чтобы его можно было удалить без переписывания заметок, пользователей, админки и базовых API.

## Основная Идея

AI не должен занимать место в рабочем интерфейсе постоянно. В обычном состоянии это компактная светящаяся иконка в правом нижнем углу поверх всех окон. При клике открывается небольшой чат над иконкой. В чате пользователь пишет команды вроде:

- `создай заметку с такими-то кредами`;
- `найди пароль от тестового стенда`;
- `оформи эту заметку как инструкцию`;
- `сделай краткое резюме выбранной заметки`;
- `добавь теги к текущей заметке`.

## Сценарии UI

### 1. Изолированный AI-Модуль

Backend:

- отдельный `AiModule`;
- отдельные таблицы с префиксом `ai_`;
- отдельные controller/service/provider файлы;
- отдельный tool registry для действий AI;
- без изменений публичного контракта базовых notes/workspace/admin сервисов, кроме маленьких явных методов, если они реально нужны;
- один общий `LlmGatewayService` как единственная точка вызова моделей.

Frontend:

- отдельная папка `features/ai`;
- отдельные компоненты `AiToggle`, `AiFloatingButton`, `AiChatPanel`, `AiSettingsPanel`, `AiBotSettings`;
- состояние AI не смешивать с `useNotesWorkspace`;
- UI вызывает только AI API, а AI API уже вызывает существующие backend-сервисы.

Удаление AI должно сводиться к:

- отключить `AiModule` в backend;
- удалить `features/ai` во frontend;
- удалить AI-пункт меню;
- удалить `ai_*` таблицы отдельной миграцией;
- базовый блокнот продолжает работать.

### 2. Переключатель AI В Меню

В боковом меню добавить пункт или toggle:

- состояние `AI выключен`;
- состояние `AI включен`;
- tooltip с коротким пояснением;
- состояние сохранять в профиле пользователя.

Если AI выключен:

- плавающая иконка не отображается;
- горячие клавиши AI не активны;
- чат не держит фоновых запросов;
- настройки AI остаются доступны из меню профиля или настроек.

Если AI включен:

- появляется плавающая иконка в правом нижнем углу;
- иконка отображается поверх модалок, панелей, редактора и меню;
- иконка не перекрывает toast-уведомления и важные кнопки.

### 3. Плавающая AI-Иконка

Расположение:

- desktop: правый нижний угол с отступом от края;
- mobile: правый нижний угол, но выше системной нижней зоны и toast-уведомлений.

Визуально:

- в стиле текущей светлой и темной темы;
- без градиентов, если текущий дизайн запрещает градиенты;
- мягкое свечение через цвет, border и opacity;
- плавная idle-анимация: легкий pulse/glow, без масштабирования элементов;
- при hover меняется цвет/прозрачность;
- при active короткое изменение opacity.

Состояния:

- `idle` - AI доступен;
- `thinking` - идет генерация, иконка показывает крутящийся индикатор;
- `error` - краткая подсветка ошибки;
- `disabled` - AI включен, но модель не настроена.

### 4. Мини-Чат Над Иконкой

При клике по иконке открывается компактное окно чата над ней.

Состав:

- список сообщений;
- поле ввода;
- кнопка отправки иконкой;
- кнопка остановки генерации;
- кнопка очистки текущего диалога;
- кнопка настроек в правом верхнем углу;
- состояние загрузки ответа;
- кастомные ошибки через общий alert/toast.

Поведение:

- окно открывается поверх всех интерфейсов;
- закрывается кликом вне окна или `Esc`;
- позиционируется так, чтобы не вылезать за экран;
- на mobile занимает почти всю ширину, но остается компактным;
- история текущего чата хранится локально в сессии, постоянное хранение можно добавить позже.

Сообщения:

- пользовательские сообщения справа;
- ответы AI слева;
- системные предложения действий отдельными компактными строками;
- если AI хочет создать/изменить заметку, показывать preview действия и кнопку подтверждения.

### 5. Настройки AI

Иконка настроек в чате открывает отдельный интерфейс настроек AI.

Разделы:

- `Общее`;
- `LLM-подключение`;
- `Безопасность`;
- `Telegram bot`;
- `VK bot`;
- `Инструкция`.

#### Общее

- включить/выключить AI;
- модель по умолчанию;
- язык ответов;
- стиль ответа: коротко, подробно, технически;
- разрешить AI создавать заметки;
- разрешить AI изменять заметки;
- разрешить AI читать секретные поля.

#### LLM-Подключение

Локальные модели не поддерживать. Все модели подключаются только через API.

Нужна одна точка подключения LLM:

- единый `baseUrl`;
- единый `apiKey`;
- единый `model`;
- единый формат request/response внутри приложения;
- поддержка OpenAI-compatible API формата;
- adapter внутри `LlmGatewayService`, чтобы frontend и tool-layer не знали конкретного провайдера.

Важно: не считать, что сторонние модели подключаются прямо через `api.openai.com`. Для сторонних LLM нужен их `baseUrl`, если провайдер поддерживает OpenAI-compatible формат. Для OpenAI используется официальный OpenAI endpoint.

Настройки:

- provider name;
- base URL;
- model id выбирается из списка доступных моделей;
- API key;
- лимит запросов в день;
- лимит токенов;
- test connection.

Каталог presets:

- OpenAI;
- OpenRouter-compatible;
- Together-compatible;
- Groq-compatible;
- DeepSeek-compatible;
- Mistral-compatible;
- Qwen-compatible;
- пользовательский OpenAI-compatible provider.

Presets должны быть только удобной подстановкой `baseUrl/model`, а не отдельной логикой.

#### Каталог И Выбор Моделей

В настройках LLM должен быть не свободный текстовый ввод модели, а custom dropdown со списком моделей, доступных текущему пользователю и текущему ключу.

Источник списка:

- backend вызывает `GET /models` у выбранного provider через `baseUrl` и сохраненный ключ;
- для OpenAI-compatible providers использовать единый adapter;
- если ключ не сохранен, показывать только публичный каталог preset-моделей, если он есть для provider;
- если ключ сохранен и provider возвращает платные модели, они появляются в списке;
- если provider перестал возвращать модель, она скрывается или помечается как устаревшая.

Визуальное разделение в dropdown:

- `Бесплатные`;
- `Платные`;
- `Неизвестно`;
- `Устаревшие`, только если нужно показать выбранную ранее модель, которой уже нет в актуальном списке.

Карточка модели в списке:

- название модели;
- короткое описание;
- индикатор качества: `●●●●○`;
- индикатор скорости: `быстрая`, `обычная`, `медленная`;
- индикатор стоимости: `бесплатно`, `дешево`, `средне`, `дорого`, `неизвестно`;
- capabilities badges: `tools`, `json`, `vision`, `embeddings`, если известно.

Важно: provider API обычно не гарантирует цену, бесплатность и качество модели. Поэтому приложение должно совмещать два источника:

- `provider models` - фактически доступные модели из API провайдера;
- `model catalog` - наш справочник метаданных: качество, цена, описание, capabilities, deprecated.

Если модель пришла от provider, но ее нет в нашем каталоге:

- показывать ее в группе `Неизвестно`;
- качество: `не оценено`;
- стоимость: `неизвестно`;
- дать пользователю возможность выбрать ее, если provider ее вернул.

Синхронизация:

- ручная кнопка `Обновить модели`;
- автообновление после сохранения/замены API key;
- автообновление по расписанию на backend, например раз в 24 часа;
- поле `last_models_sync_at`;
- поле `models_sync_status`;
- поле `models_sync_error`, без секретов и токенов;
- старые модели автоматически скрывать из основного списка, если они больше не приходят от provider;
- выбранную ранее модель не сбрасывать молча: показать предупреждение и предложить выбрать замену.

Backend-сервисы:

- `AiModelCatalogService` - локальный справочник моделей и метаданных;
- `AiModelSyncService` - синхронизация доступных моделей с provider;
- `AiProviderModelsRepository` - хранение результатов синхронизации;
- `LlmGatewayService` - только выполнение запросов к выбранной модели.

Таблицы:

- `ai_model_catalog` - статический/обновляемый справочник моделей;
- `ai_provider_models` - модели, реально доступные конкретному provider/key;
- `ai_user_llm_settings` - выбранный provider/model/key и sync state.

UI-состояния:

- `Модели не загружены`;
- `Обновляем список`;
- `Нет доступных моделей`;
- `Ключ нужен для списка моделей`;
- `Выбранная модель устарела`;
- `Провайдер не вернул цены, стоимость неизвестна`.

API key:

- хранить только на backend;
- шифровать в БД;
- не отдавать на frontend;
- показывать в UI только маску, например `sk-...A9x2`;
- полный ключ после сохранения нельзя посмотреть в приложении;
- если пользователь потерял ключ, он создает новый у провайдера и заменяет его в настройках;
- в UI нужны действия `Заменить ключ`, `Удалить ключ`, `Проверить подключение`;
- при удалении ключа удаляется зашифрованное значение, hint и дата проверки;
- admin не видит чужие ключи в открытом виде.

Хранение:

- `api_key_encrypted` - зашифрованный ключ;
- `api_key_hint` - безопасная маска/последние символы;
- `api_key_updated_at`;
- `last_connection_check_at`;
- `last_connection_check_status`.

Шифрование:

- отдельный env `AI_CREDENTIALS_ENCRYPTION_KEY`;
- AES-256-GCM или такой же проверенный механизм, как для секретных полей;
- ключ расшифровывается только на время запроса к LLM;
- ключ нельзя писать в logs, audit details, stack traces и toast/errors.

Подсказка в UI:

`Полный API key не отображается после сохранения. Если вы потеряли ключ, создайте новый у провайдера и замените его здесь.`

#### Безопасность

Настройки:

- запрет отправки secret/password/token полей в AI;
- режим подтверждения перед раскрытием секрета;
- режим подтверждения перед созданием/изменением заметки;
- журнал AI-действий;
- запрет ответов с полными паролями в Telegram/VK.

#### Telegram Bot

Подключение должно быть максимально простым:

- поле `bot token`;
- кнопка `Сохранить`;
- кнопка `Проверить`;
- кнопка `Включить webhook`;
- поле с readonly webhook URL и кнопкой копирования;
- список разрешенных `chat_id`;
- toggle `разрешить ответы с секретами`, по умолчанию выключен.

Мини-инструкция во всплывающем окне настроек:

1. Открыть Telegram.
2. Найти `@BotFather`.
3. Отправить `/newbot`.
4. Указать имя и username бота.
5. Скопировать token.
6. Вставить token в настройки сайта.
7. Нажать `Проверить`.
8. Нажать `Включить webhook`.
9. Написать боту любое сообщение.
10. В настройках сайта добавить свой `chat_id` в разрешенные, если он не добавился автоматически.

#### VK Bot

Подключение:

- поле `group id`;
- поле `access token`;
- поле `secret key`;
- поле `confirmation code`;
- readonly callback URL с кнопкой копирования;
- кнопка `Проверить`;
- список разрешенных пользователей/чатов;
- toggle `разрешить ответы с секретами`, по умолчанию выключен.

Мини-инструкция во всплывающем окне настроек:

1. Создать или открыть сообщество VK.
2. Перейти в `Управление` -> `Работа с API`.
3. Создать ключ доступа сообщества с правами на сообщения.
4. Перейти в `Callback API`.
5. Скопировать callback URL из настроек сайта и вставить его в VK.
6. Скопировать `confirmation code` из VK и вставить в настройки сайта.
7. Указать `secret key`, если он используется.
8. Нажать `Проверить`.
9. Включить события входящих сообщений.
10. Добавить нужных пользователей/чаты в разрешенные.

#### Возможности Ботов

Бот должен уметь выполнять все действия, которые доступны пользователю с такими же правами в UI:

- поиск заметок;
- чтение заметок;
- создание заметок;
- редактирование заметок;
- удаление/корзина/восстановление;
- работа с тегами;
- работа с избранным и закреплением;
- работа с шаблонами;
- работа с версиями;
- работа с вложениями, если это безопасно для конкретного канала;
- создание временных ссылок;
- ответы по статистике или админке только для пользователя с ролью `admin`.

Бот не должен иметь отдельные расширенные права. Все действия проходят через тот же permission/ownership layer, что и UI.

## UX-Поток

1. Пользователь включает AI в меню.
2. В правом нижнем углу появляется AI-иконка.
3. Пользователь нажимает на иконку.
4. Открывается мини-чат.
5. Пользователь пишет команду.
6. Backend отправляет запрос в выбранную модель.
7. AI возвращает текст или структурированное действие.
8. Для действий с заметками UI показывает preview.
9. Пользователь подтверждает действие.
10. Backend выполняет действие существующими сервисами заметок.
11. UI обновляет дерево и выбранную заметку.

## Архитектурные Ограничения UI

- AI-чат не должен напрямую изменять frontend state заметок без ответа backend.
- Все действия AI должны проходить через существующие API.
- Нельзя давать модели прямой доступ к БД.
- Нельзя отправлять секретные поля в модель без явного разрешения.
- Нельзя делать локальные LLM runtime или Ollama-интеграции в MVP.
- Нельзя размазывать AI-код по существующим notes/workspace/admin модулям.
- Все вызовы моделей идут через один `LlmGatewayService`.
- Все команды AI идут через один `AiToolRegistry`.
- Telegram/VK adapters только принимают входящее сообщение, определяют пользователя и передают команду в AI-модуль.
- Все ошибки показывать через общий toast/alerting.
- Все всплывающие окна и tooltips должны использовать общий portal-layer.
- Дизайн должен повторять текущие светлую и темную темы.

## Tool Registry

AI и боты не вызывают сервисы напрямую. Они выбирают действие из registry:

- `notes.search`;
- `notes.read`;
- `notes.create`;
- `notes.update`;
- `notes.delete`;
- `notes.restore`;
- `notes.tags.set`;
- `notes.favorite.set`;
- `notes.pinned.set`;
- `templates.list`;
- `templates.createNote`;
- `versions.list`;
- `versions.restore`;
- `attachments.list`;
- `attachments.attachToNote`;
- `shareLinks.create`;
- `admin.users.list`, только admin;
- `admin.stats.read`, только admin.

Каждый tool:

- принимает `userId`;
- проверяет роль и ownership;
- валидирует payload;
- возвращает preview, если действие опасное;
- пишет запись в `ai_audit_logs`.

## Бот-Поток

1. Telegram/VK присылает webhook.
2. Bot adapter проверяет подпись/token/secret.
3. Adapter определяет связанного пользователя и разрешенный chat/user id.
4. Сообщение передается в `AiCommandService`.
5. `AiCommandService` вызывает `LlmGatewayService`.
6. Модель возвращает ответ или tool-call.
7. Tool registry проверяет права пользователя.
8. Для опасных действий бот просит подтверждение короткой командой.
9. После подтверждения действие выполняется.
10. Бот возвращает короткий ответ.

Для секретов:

- по умолчанию бот не отправляет полные secret/password/token значения;
- можно вернуть название найденной заметки и ссылку на приложение;
- полное значение только при явном разрешении в настройках и явной команде пользователя.

## Минимальный MVP

1. Toggle AI в боковом меню.
2. Плавающая AI-иконка.
3. Мини-чат.
4. Настройки единого LLM provider: `baseUrl`, `model`, `apiKey`.
5. Preset `OpenAI`.
6. Preset `Custom OpenAI-compatible`.
7. Dropdown выбора модели из синхронизированного списка с группами `Бесплатные`, `Платные`, `Неизвестно`.
8. Ручное обновление моделей и автообновление после сохранения ключа.
9. Команды:
   - поиск по заметкам;
   - создание заметки;
   - форматирование текущей заметки;
   - краткое резюме заметки.
10. Подтверждение перед записью изменений.
11. Журнал AI-действий.
12. Настройки Telegram/VK с инструкцией, но сами боты можно вынести во второй этап.

## Риски

- AI может раскрыть секреты, если не ограничить доступ.
- Бесплатные модели могут работать нестабильно или медленно.
- Бесплатные API-провайдеры могут менять лимиты и доступность.
- Provider может вернуть модель без информации о цене и качестве; в таком случае UI обязан показывать `неизвестно`, а не угадывать.
- Автоматическое удаление старых моделей не должно ломать уже выбранную модель молча.
- Боты в мессенджерах опасны для передачи паролей.
- Prompt injection через содержимое заметок нужно учитывать с первого этапа.
- Если AI-модуль размазать по проекту, его будет сложно удалить. Поэтому все новые AI/Bot части должны оставаться в отдельном модуле.
